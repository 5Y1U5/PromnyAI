Claude Haiku 5.5 と Sonnet・Opus の使い分け — 仕事ごとに決める「使うモデル」と「人の確認」の表

2026-10-09

「口コミ返信の下書きも提案書も、Claude の同じモデルで書いている」。そこへ10月7日、小さなモデルの Claude Haiku 5.5 が発表されました。

発表のたびに「どれが一番か」を決め直すと、社外に出す文章を誰が見るかまで揺れます。何を決めておけば迷わないのか。

この記事の結論

Anthropic の説明では、要約や分類のような数の多い仕事に向くのが Haiku 5.5 です。日々の文書づくりは Sonnet 5.5、慎重な判断が要る複雑な仕事は Opus 5.5 とされています。この「使うモデル」とは別の列で、「人の確認」を仕事ごとに決めます。

10月9日、まだ 5.5 を選べない PromnyAI で、4.5 Haiku と sonnet 5 に同じ短い仕事3本を頼みました。差はトークンより仕上がりに出ました。口コミへの返信は、どちらのモデルの文にも人が直す箇所がありました。

9月下旬からの3つの発表 — Haiku 5.5 は「数が多く、費用を気にする仕事」向け

Anthropic は9月22日から10月7日にかけて、Claude の新しいモデルを3つ続けて発表しました。どのモデルがどんな仕事に向くかは、発表の中に書かれています。

  • Claude Opus 5.5（9月22日）：慎重な判断が要る、複雑な仕事向け（Sonnet 5.5 の発表での説明）
  • Claude Sonnet 5.5（9月28日）：範囲がはっきりした日々の仕事や、整った文書・スライドづくり向け
  • Claude Haiku 5.5（10月7日）：数が多く、費用を気にする仕事向け。例は要約や分類。最も速いモデルなので、問い合わせへのその場の対応にも向くとしています

Haiku 5.5 の発表は、範囲の狭い仕事に最も向く、とも書いています。込み入ったプログラミングの仕事には、引き続き Sonnet 5.5 と Opus 5.5 のほうが向くという説明です。

値段も大きく違います。開発者向けの料金では、Haiku 5.5 は入力・出力とも Sonnet 5.5 の20分の1です（10万トークンまでの依頼。2026年10月9日に Anthropic の発表ページで確認）。ただし、月の利用量をトークン数で数えるサービスでは、安いモデルに替えても、画面で減るトークン数が少なくなるとは限りません。

この説明を、自社の仕事の振り分けに当てはめます。

振り分け表は「使うモデル」と「人の確認」を別の列にする

発表の説明を借りると、仕事ごとにどのモデルから試すかの見当が付きます。ここでは、人の確認を同じ列にまとめず、別の列に分けます。小さいモデルで足りるかと、社外に出す前に人が見るかは、別の問いだからです。

たとえば口コミへの返信は短い文章なので、小さいモデルでも書けます。それでも、お店の名前で外に出る文章です。

読者の疑問

「大きいモデルに任せれば、人の確認は減らせるのでは」

確認が要るかどうかは、モデルの大きさではなく、その文章を誰が読むかで決めます。社外の人が読む文章なら、どのモデルで書いても出す前に人が読みます。PromnyAI で 4.5 Haiku と sonnet 5 が実際に書いた口コミへの返信文は、次の章で見比べます。

仕事ごとに2つの列を並べると、次のような形になります。

仕事使うモデル（まず試すもの）人の確認
打ち合わせメモの社内向け要約Haiku日付と担当だけ、元のメモと見比べる
問い合わせの振り分けHaiku受け取った担当が、中身を読むときに見る
口コミ・問い合わせへの返信の下書きHaiku と Sonnet で試して決める出す前に必ず人が読む
提案書・企画書の下書きSonnet。Sonnet の下書きに直す箇所が多ければ Opus でも試す出す前に必ず人が読む

使うモデルの列は、Anthropic の説明を出発点にした仮置きです。自社の文面で試してから書き換えます。人の確認の列は、その文章を社外の人が読むか、お金や約束に触れるかで決めます。モデルの説明からは決まりません。

PromnyAI で同じ仕事を2つのモデルに頼むと、差はトークンより仕上がりに出た

仮置きにした使うモデルの列を、試験用に作った文面で確かめてみます。私たちの PromnyAI の一覧には、2026年10月9日時点で 5.5 の3つはまだありません。画面の表示名で書くと、選べる Claude は Opus 5・sonnet 5・4.5 Haiku・Fable 5.1 の4つです。新しいモデルが並んだ日にすぐ試せるよう、先に表を作っておきます。今回は、いま選べる 4.5 Haiku と sonnet 5 で試しました。

10月9日に、Professional プランで、試験用に作った短い仕事3本を、2つのモデルに1回ずつ頼みました。

01 要約

打ち合わせメモ（223字）を3行にまとめるよう頼みました。sonnet 5 は3行で、4.5 Haiku は4文の1段落で返しました。

02 振り分け

問い合わせ5件を4つの分類に分けるよう頼みました。5件とも、2つのモデルで同じ分類でした。

03 口コミ返信

星3つの口コミへの返信を200字程度で頼みました。sonnet 5 は来店のお礼から書き始めました。4.5 Haiku の書き出しは「お返事ありがとうございます」でした。口コミはお店への返事ではないので、この書き出しは場面に合っていません。

2つのモデルの仕上がりの差は、指示の守り方と書き出しに出ました。口コミ返信では、もう1つ気づいたことがあります。sonnet 5 は「提供時間の短縮とお待たせする際の声かけ徹底に努めてまいります」と書きました。4.5 Haiku も「スタッフの意識向上と業務改善に取り組んでまいります」と書いています。どちらも店がまだ決めていない約束で、出す前に人が直す箇所です。

消費したトークンは、トークン管理の画面で1本ずつ読みました。どの仕事も1本あたり約2,250〜2,420トークンで、2つのモデルの差は10〜27トークンでした。この3本の短い仕事では、モデルを替えてもトークンの減り方はほとんど変わりませんでした。長い資料や何往復ものやり取りは、まだ測っていません。Haiku の安さを理由にモデルを替えるかどうかは、使っているサービスの利用量の画面で、1本あたりの数字を見てから決めます。

結果を表に戻すと、振り分けの行は Haiku のままにします。要約と口コミ返信の行は、4.5 Haiku が形や書き出しを外したので、使うモデルをいったん Sonnet に書き換えます。新しい Haiku が使えるようになったら、同じ文面で確かめ直します。提案書の行は今回試していないので、仮置きのままです。人の確認の列は、どの行も変えません。

新しいモデルが出た日に見直すのは「使うモデル」の列だけ

表ができたら、新しいモデルの発表は、使うモデルの列を見直す合図にします。自社で使っているサービスの一覧に新しいモデルが並んだときに、次の順で確かめます。

  • 表の仕事から、数の多いものを1〜2本選ぶ
  • いまのモデルと新しいモデルに、同じ文面で1回ずつ頼む
  • 指示どおりの形になっているか、書き出しの言葉が相手と場面に合っているか、日付や担当に抜けや誤りがないかを見比べる
  • トークン管理など利用量の画面で、1本あたりの消費量を書き留める
  • 使うモデルの列を書き換える。人の確認の列はそのまま残す

人の確認の列を見直すのは、その文章を読む相手が変わったときです。社内向けだった要約を、お客様へのお知らせに使い始めたときに、その行の確認を足します。新しいモデルに切り替える日程や戻し方まで決める手順は、別の記事「AIの新モデルへの切り替え手順」に書いています。

モデルの振り分け表は、数の多い仕事5つから作り始める

ここまでの表も見直しの手順も、最初から全部の仕事でそろえる必要はありません。社内で数の多い仕事を5つ書き出し、2つの列を埋めるところから始めます。

表が1枚あれば、新しいモデルが使えるようになった日に見直すのは、使うモデルの列だけです。人の確認の列はモデルの発表では動かさない、と決めておけば、発表のたびに迷わずに済みます。
